Memory와 MemoryPool

Memory는 크기를 보고 어느 풀로 보낼지 정하는 배정 담당이고, MemoryPool은 한 가지 크기의 블록만 쌓아 두는 보관함이다. 둘이 어떻게 나눠 일하는지, 호출 한 번이 두 클래스를 어떻게 오가는지 따라가 본다. Step 4-1 완료

1. 한 문장씩: 누가 무엇을 아나

물품 보관소로 비유하면 Memory는 접수 창구, MemoryPool은 같은 크기 상자만 넣는 선반 하나다. 창구는 선반 48개를 갖고 있고, 손님이 맡긴 물건 크기를 보고 맞는 선반으로 보낸다.

Memory (GMemory 하나)
접수 창구: "이 크기면 저 선반"
  • 요청 크기 + 헤더 16 = 블록 크기를 계산한다
  • 블록 크기로 poolTable_을 보고 담당 풀을 고른다
  • 4096을 넘으면 풀 없이 _aligned_malloc으로 직접 처리한다
  • 헤더를 붙이고(AttachHeader) 떼는(DetachHeader) 일을 한다
  • 풀 48개를 소유한다 (pools_, 소멸자에서 delete)
MemoryPool (크기마다 하나)
선반 하나: "내 크기 블록만 넣고 뺀다"
  • 자기 블록 크기(allocSize_, 예: 128) 하나만 안다
  • 쉬는 블록을 SLIST 스택에 쌓는다: Push / Pop
  • 비었을 때 Pop하면 새 블록을 _aligned_malloc으로 만든다
  • 다른 풀이나 요청 크기는 모른다. 헤더의 allocSize_는 0(풀 안)인지만 본다
  • 락이 없다. SLIST 원자 연산 + 카운터 Atomic

MemoryPool은 Memory를 모른다. 그래서 다른 곳에서도 쓸 수 있다: ObjectPoolBase는 Memory를 거치지 않고 자기 전용 MemoryPool 하나를 직접 갖는다.

2. Memory 안의 두 멤버: pools_와 poolTable_

pools_는 풀 48개를 소유하는 목록이고, poolTable_은 블록 크기(인덱스)마다 그 풀을 가리키기만 하는 4097칸 배열이다. 여러 칸이 같은 풀을 가리킨다. 블록 크기를 바꾸거나 풀 타일을 눌러 본다.

Memory (GMemory)
poolTable_[4097] — MemoryPool* 4097칸. 인덱스 = 블록 크기. 소유하지 않음
01024204830724096
pools_ : vector<MemoryPool*> — 48개를 new로 만들고 ~Memory()에서 delete. 소유

이렇게 둘로 나눈 이유: 풀을 고를 때 48개를 하나씩 비교하지 않고 poolTable_[blockSize] 한 칸만 읽으면 된다 (O(1)). 표는 생성자에서 한 번 채우고 그 뒤로 읽기만 하므로, 여러 스레드가 동시에 읽어도 락이 필요 없다.

3. 호출 한 번 따라가기: Allocate(100) → Release → Allocate(110)

어느 클래스가 무슨 일을 하는지 칸으로 나눴다. 이름이 같은 두 allocSize_를 주의해서 본다: 풀의 allocSize_(128, 풀 블록 크기, 바뀌지 않음)와 헤더의 allocSize_(Memory가 적는 값, 풀 안에서는 0).

5. 생기는 순서와 사라지는 순서

Memory() 생성자는 AddPool을 48번 부른다. 매번 풀을 하나 만들어 pools_에 넣고, 바로 앞 풀 크기 + 1부터 자기 크기까지 poolTable_ 칸을 채운다. 다음을 눌러 표가 채워지는 것을 본다.

01024204830724096
main() 첫 줄: CoreGlobal 생성
 └ GMemory = new Memory()          // 가장 먼저 만든다 (다른 전역이 할당할 수 있으므로)
    ├ pools_.reserve(48)
    ├ AddPool(32) … AddPool(4096)     // 풀 48개 생성 + poolTable_ 채우기
    └ ASSERT(마지막 풀 == 4096)        // 표 끝까지 빈칸이 없는지 확인

main() 끝: CoreGlobal 소멸
 └ delete GMemory                    // 가장 마지막에 지운다
    └ ~Memory(): pools_의 풀마다 delete
       └ ~MemoryPool(): SLIST에서 하나씩 Pop → _aligned_free  // 쉬는 블록만

아직 Release 안 된 블록              // 풀은 밖에 나간 블록을 모른다 → 그대로 누수
